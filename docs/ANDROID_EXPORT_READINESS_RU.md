# Android-экспорт Telegram: реальная готовность и безопасный путь к первому подключению

Проверено 26.10.2026. Это план разработки и оценка инженерной готовности, **не** сертификат безопасности и не результат испытания на реальном аккаунте.

## Цель и текущий объём

Android-приложение **Vault Exporter** сохраняет выбранный доступный облачный чат на телефоне в локальный зашифрованный .tva-архив, с проверкой целостности и повторным запуском после обрыва. Без стороннего сервера и передачи пользовательской истории в GitHub. Секретные чаты и защищённый от копирования контент исключены.

**Текущая основа:** отдельная QA-ветка `fix/vault-integration-tdlib-mock-20261026` поверх `main@375fef2`. Не заменять проект другим клиентом и не делать merge в `main` до критических Android-проверок.

## Политика Telegram и аккаунт

1. Telegram разрешает сторонние приложения через свой MTProto API; TDLib — официальная библиотека для клиентов. Но Telegram предупреждает о наблюдении за аккаунтами, которые входят через неофициальные клиенты, и о блокировках за злоупотребления. **Нулевой риск блокировки обещать нельзя**.
2. Получить собственный developer `api_id/api_hash` на https://my.telegram.org/apps, не брать чужие/образцовые ID; держать исходные credentials за пределами GitHub и артефактов CI. Они присутствуют в собственном Android build, поэтому бинарный клиент также нужно считать недоверенной средой для секретов.
3. Не обходить FLOOD_WAIT и ограничения контента, не делать невидимых действий от лица пользователя и не выполнять массовые скачивания без явного выбора чата.
4. Перед реальным аккаунтом использовать только offline synthetic, затем **Telegram test DC** с изолированной тестовой учётной записью. Тестовый DC не доказывает поведение production. Основной аккаунт подключать только при отдельном осознанном согласии владельца.
5. Название публикуемого приложения — `Vault Exporter` с явным описанием «неофициальный клиент, использует Telegram API»; не использовать официальный логотип Telegram.

Официальные источники: https://core.telegram.org/api/terms ; https://core.telegram.org/api/obtaining_api_id ; https://core.telegram.org/tdlib/ ; https://core.telegram.org/api/content-protection .

## Исследованные реализации и решения

- https://github.com/tdlib/td/tree/master/example/android — официальный Android builder для `libtdjson.so`; использовать закреплённый commit, `JSON` interface, только `arm64-v8a`, проверять ELF ABI, экспортируемые JSON-символы, лицензии и sha256.
- https://github.com/TGX-Android/Telegram-X — полнофункциональный Android TDLib-клиент; подходы: проверяемые Android-сборки и локальная конфигурация API. Нельзя механически копировать GPLv3-код в наш проект без соблюдения лицензии.
- https://github.com/Pranavraut033/telegram-backup и https://github.com/hoelee/telegram-backup-downloader — примеры сохранения прогресса загрузки, ошибок и ограничений на файловые операции. Это Python/Telethon, не готовая безопасная Android-реализация.
- https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/export/export_api_wrap.cpp — экспорт Telegram Desktop с `account.initTakeoutSession`, `invokeWithTakeout`, диапазонами и ограниченной параллельностью. Официальная спецификация https://core.telegram.org/api/takeout . Это **перспективное отдельное архитектурное исследование**, а не повод менять уже проверенный TDLib-путь или копировать GPL-код.

## Факты о нашем коде

- Реализованы `getChatHistory`, `downloadFile`, per-chat checkpoint, AES-GCM encryption, verifier и чтение статусов TDLib через JNI.
- Для `420 FLOOD_WAIT_N` код ждёт требуемый сервером период (до 120 секунд) или останавливает экспорт с сохранением прогресса при более долгом ожидании.
- Чаты с `has_protected_content` и тип `chatTypeSecret` не экспортируются; проверяется также `can_be_saved=false`.
- В Android manifest запрещены backup и cleartext; отдельная проверка безопасности требует только разрешение INTERNET, offline debug/test build не подключается к production Telegram.
- **Проверено:** offline JVM экспорт 320 синтетических сообщений, media-album и 48 МиБ потоковое медиа в 32 МиБ heap; интеграционное возобновление; JNI mock. **Не проверено:** реальный Android APK, TDLib connection, авторизация, реальная история, производственный трафик.
- **Проверка публичности 26.10:** GitHub `Caprifan2078/telegram-vault-exporter-android` = Public. В дереве QA-ветки нет *.apk/*.tva/*.zip/*.session/ключей; это проверка имён файлов, не полный аудит опубликованных данных.
- Существующий локальный рабочий environment не имеет Android SDK/NDK или проверенного `libtdjson.so`; Android APK не собиралась в этой проверке.

## Ближайшие практические вехи (без бесконечных тестов)

### Gate A: воспроизводимая локальная Android QA-сборка
- Получить/установить Android SDK/NDK, закрепить проверенный commit официальной TDLib и собрать `libtdjson.so` для arm64.
- Прогнать `scripts/verify_tdlib_elf.py`, Gradle build gates, сформировать SHA-256 APK и задокументировать точные инструменты. Никаких реальных Telegram credentials в GitHub CI.
- Успех: подписанная debug/test APK устанавливается и запускается на устройстве, просматривает синтетическую переписку и проверяет созданный архив.

### Gate B: изолированный сетевой тест TDLib
- Только после прохождения Gate A: test DC и отдельный тестовый аккаунт, не основной.
- Снять сетевой след: только ожидаемая сеть Telegram, без аналитики/посторонних доменов; проверить, что логин/пароль не журналируются.
- Успех: выбор одной разрешённой тестовой переписки, локальный экспорт, сравнение с оригиналом, остановка/возобновление, logout, проверка отсутствия незашифрованных остатков.

### Gate C: ограниченный production-пилот
- Только после сетевого аудита и согласования владельца. Небольшая собственная/согласованная переписка; лимиты скорости и остановка по серверным ограничениям; проверка отсутствия нежелательных действий и сохранности данных.
- Успех: результаты на реальном Android, корректная защита статуса авторизации, надёжное восстановление, независимый review security.
- Не проводить массовый экспорт и не считать APK релизом до прохождения этих ворот.

## Когда помощь владельца действительно потребуется

**Сейчас:** ничего секретного присылать не нужно. Сохранять основной аккаунт вне испытаний.

**Перед Gate B:** потребуется отдельный тестовый Telegram-аккаунт и локально созданные `api_id/api_hash` приложения (их вводить только в доверенный локальный build, не в чат/репозиторий). Может понадобиться установка тестовой APK на Android и обратная связь об успешном логине.

**Перед Gate C:** отдельное явное решение владельца, хочет ли он рисковать подключением реального аккаунта и какой небольшой чат доступен для эксперимента.

## Оценка готовности (субъективная, не покрытие тестами)

- Локальный экспортный движок и офлайн-сценарии: ~80%.
- Приватность/целостность при локальном экспорте: ~60–65%; независимого security audit нет.
- Ограничения API/консервативная обработка TDLib: ~55–60%; живого подключения не было.
- Android-installable pipeline: ~20–25%; native toolchain/TDLib и APK отсутствуют.
- Реальный export с Telegram на Android: **0% подтверждённых E2E-проверок** (это не утверждение, что код неспособен).
- Общая инженерная готовность до безопасного, проверенного alpha-пилота: **ориентировочно 40%**. Проценты отражают экспертную оценку риска/этапов, не вероятность успешного экспорта.

Избегать повторных дорогих synthetic тестов без конкретной гипотезы; главное препятствие сейчас — не число JVM тестов, а официальный Android TDLib build + device QA.
