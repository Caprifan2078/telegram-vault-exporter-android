# Первый сетевой вход: только Telegram TEST DC

**На 27.10.2026:** полноценный экспорт реальной личной переписки не испытан. Не подключайте основной аккаунт к QA-экспортёру. Не покупайте готовые Telegram-аккаунты: возможны чужие активные сеансы, восстановление владельцем и блокировки.

## Нужна ли отдельная SIM?

**Пока нет.** Официальная Telegram API документация описывает общедоступные тестовые номера `99966XYYYY`, где `X` — 1, 2 или 3, `YYYY` — четыре цифры. Код — цифра `X`, повторённая пять раз (например, X=2: `22222`). Эти номера существуют только на Test DC, являются **общедоступными**, и данные в них могут быть прочитаны другими людьми и стираются Telegram. Регистрация новых тестовых номеров может не работать. Никаких настоящих имён, фотографий, личных сообщений, контактов или иных конфиденциальных данных там не хранить.

В новой сетевой Android QA-сборке:
- тестовый сервер закреплён в TDLib через `use_test_dc=true`, production недоступен;
- ещё до TDLib транспорт отклоняет любые номера, кроме `+99966XYYYY` / `99966XYYYY` (X=1–3);
- создание тестового аккаунта **не выполняется автоматически**: пользователь должен прочитать предоставленные Telegram условия, подтвердить согласие и указать вымышленное имя;
- разработчик вводит собственный `API ID` и `API Hash` непосредственно на устройстве, после чего приложение очищает ссылки на них из Activity; они не встроены в публичный APK и не отправляются в GitHub;
- запись/удаление сообщений, массовые рассылки и другие действия стороннего клиента запрещены на уровне TDLib API allowlist; единственное новое изменение профиля — явная тестовая регистрация;
- полноценная работа на физическом Android с авторизацией и восстановлением архива ещё требует независимой проверки; безопасность не гарантирована на 100%.

## Если реально понадобится другое подключение

Лучший резервный вариант — **свой новый номер SIM/eSIM** и отдельный аккаунт, созданный через официальное приложение Telegram. Не покупайте восстановленные/готовые аккаунты у продавцов. Это вариант для **отдельного последующего решения о production-пилоте**, не для текущей `networkDc` APK: она блокирует обычные номера и production DC.

## Что пользователь будет делать после готовой APK

1. Установить только QA `networkDc` из проверенного артефакта GitHub или из предоставленного файла.
2. Получить при необходимости *свой* API ID/Hash на официальном https://my.telegram.org/apps; не передавать коды, Hash, телефон или сессии в чат, репозиторий и скриншоты.
3. Ввести API ID/Hash только внутри APK и подтвердить соединение с Test DC.
4. Попробовать **один** тестовый номер и код; при неуспехе/лимите остановиться, не перебирать номера.
5. Если Telegram попросит новую регистрацию, прочитать условия, согласиться только при желании и использовать вымышленное имя.
6. Экспортировать только публично безопасные, специально созданные тестовые сообщения. Не использовать основной Telegram-аккаунт.
7. Сохранить локальный зашифрованный архив и проверить его целостность. Не загружать этот архив в GitHub.
