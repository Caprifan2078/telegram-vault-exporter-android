# TVA1 — формат переносимого архива Telegram Vault (черновик v1)

**Статус:** экспериментальная спецификация, не совместимая напрямую с Telegram Desktop.
Создаёт `Vault Exporter`, расшифровывает будущий `Vault Reader`. Ни один сервер не нужен.

## Внешний контейнер

`filename.tva` — двоичный поток, состоящий из:

* 4 байта ASCII `TVA1`;
* 16 случайных байт соли;
* 4 байта PBKDF2 iteration count, big endian, сейчас 400000;
* 4 байта plaintext block size, big endian, сейчас 262144;
* 8 байт случайного nonce-prefix;
* далее блоки AES-256-GCM.

Ключ: PBKDF2-HMAC-SHA256(пароль пользователя, salt, 400000, 32 байта).

Каждый блок: 4 байта длины N (0..262144); затем N байт зашифрованного текста и тег GCM 16 байт.
IV 12 байт: 8 байт nonce-prefix + 4 байта counter (big endian, с нуля).
AAD: 36 байт заголовка + 4 байта counter + 1 байт final flag (0 или 1).
Конец потока — обязательный заключительный блок с N=0, final flag=1, 16-байтным тегом.
После этого блока не допускаются дополнительные байты. Перестановка, вставка или удаление
блоков обнаруживается аутентификацией. Версия и размеры проверяются до выделения памяти.
Пароль НИКОГДА не сохраняется в TVA1.

**Не открывать содержимое архива до проверки тегов блоков!** Нельзя читать
незашифрованную информацию из неаутентифицированного блока.

### После расшифровки

UTF-8 ZIP со следующими записями:

`manifest.json` — метаданные экспорта, идентификатор чата, дата UTC, число сообщений,
число загруженных / пропущенных медиа. Поле `history_end_reached` не означает
гарантированную абсолютную полноту истории Telegram.

`messages/page-000001.jsonl`, `messages/page-000002.jsonl` и т.д.
Каждая строка — оригинальный JSON-объект `message` из TDLib. Включает `id`, `chat_id`,
`date` (Unix seconds), `sender_id`, `is_outgoing`, `content`, возможные replies / edits,
если Telegram API их возвращает. Записи могут идти в обратной хронологии.

`media-index/page-000001.jsonl` и т.д. Каждая строка:
```
{"message_id":123,"file_id":456,"category":"round_video","path":"media/123/456.mp4","mime_type":"video/mp4","original_name":"","sha256":"...","bytes":23849}
```
`participants.json` — сведения о найденных отправителях: kind (user или chat), id и доступное на момент выгрузки имя. Если Telegram не отдаёт имя, остаётся ID.

Файлы `media/...` — исходные байты медиа без перекодирования. Доступные категории:
`round_video`, `voice`, `photo`, `video`, `animation`, `audio`, `sticker`, `document`.

Рекомендуемый алгоритм читалки:
1. Запросить пароль и потоково проверить GCM-теги + обязательный конечный блок.
2. Прочитать ZIP только как **данные** (не исполнять HTML, скрипты, URI, вложения).
3. Проверить имена путей внутри ZIP, размер распаковки и SHA-256 медиа.
4. Сопоставить `(message_id, media-index[].path)` и отображать по дате и sender_id.
5. При отсутствии медиа показывать плашку «Файл недоступен», не терять сообщение.
6. Различать ID и reply links внутри чата, выделить кружочки / голосовые.
7. Хранить избранное читателя отдельно от неизменяемого исходного архива.

**Ограничения:** нет побайтовой идентичности с Telegram Desktop result.json или HTML;
нет гарантий о восстановлении удалённых для всех сообщений, секретных чатов,
защищённого контента, медиа с истёкшей доступностью.

## Возобновление загрузки в Android

Промежуточные файлы `TVS1` находятся в закрытой папке самого приложения.
Каждая страница истории и каждый скачанный медиафайл шифруются AES-256-GCM
ключом, полученным через HMAC-SHA256 от защищённого секрета TDLib.
Checkpoint обновляется **после** полного сохранения страницы и её основных медиа.
При перезапуске непринятый checkpoint не двигается, уже сохранённые медиа
проверяются и используются повторно. После успешной проверки конечного `.tva`
стейджинг удаляется; при явном выходе из отдельного сеанса Vault также удаляется.

**Обратная совместимость:** TVA1 остается тем же криптоконтейнером; новые JSON-поля
и `participants.json` необязательны для более ранних ридеров. Формат не является
побайтовой копией экспорта Telegram Desktop.
