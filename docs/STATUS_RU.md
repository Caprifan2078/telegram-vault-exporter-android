## Подтверждённое состояние

**Android alpha, не production APK.** Реализованы движок экспортирования, шифрование TVA, этапное сохранение/возобновление, проверка архива, синтетические файлы, UI и шлюз TDLib. Наличие исходного кода не подтверждает работоспособность реального Telegram-экспорта.

Незакрытые ограничения:

1. Отсутствует проверенная официальная Android arm64 `libtdjson.so` в исходном репозитории. Android SDK/NDK и подлинная TDLib нужны для функциональной сборки.
2. Не проверены production Telegram login, настоящий экспорт чатов, Android end-to-end на физическом устройстве и безопасность основного аккаунта.
3. Смешанный million-word Android стресс-тест в исторических прогонах не завершился подтверждённым архивом: встречались `IOException` и незавершённое взаимодействие с DocumentsUI. Первопричина не установлена.
4. Масштабы 100 ГБ, ZIP64 и ограничение места, прерывания Android background worker требуют отдельных испытаний.
5. Независимый аудит безопасности, релизные проверки и разрешение на production-сборку ещё не завершены.

## QA-исправления в отдельной ветке

- Предыдущий интеграционный тест `expected history outage` завершался раньше ожидаемого обрыва: Java fake TDLib не возвращал `id`/размер файла и не моделировал `cancelDownloadFile`, `getFile` и удаление plaintext кэша. Фальшивый ответ нарушал новую fail-closed проверку приватности.
- Mock теперь возвращает идентификаторы файлов и корректно удаляет фиктивные кэш-файлы; fail-closed логику production `cloudDownload` при этом не ослабляли.
- Тесты приведены в соответствие с уже реализованной обработкой `messagePaidMedia` и `messageChatChangePhoto`: проверяются корректные варианты и безопасное отклонение неправильных.
- В `ExportEngine` учтён `@type` как обозначение вида link preview, когда поле `type` отсутствует: неизвестный богатый предпросмотр не может пройти как простой текст.
- Public-only GitHub QA теперь включает offline engine integration, транспортный mock TDLib и host JNI проверки. Отдельный CI-contract перепроверяет **фактически существующий** минимальный workflow вместо ссылок на удалённую при миграции историческую конфигурацию.
- Workflow не собирает APK, не обращается к Telegram, не получает ключей, не публикует артефактов и остаётся отключённым для private hosted runners.
