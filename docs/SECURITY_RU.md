# Обзор безопасности — Telegram Vault Exporter alpha

## Модель угроз
Защищаем от: случайного отправления в облако, сторонних сервисов, доступа других
обычных Android-приложений к внутренней папке, копирования архива без знания пароля,
случайной порчи, потери соответствия медиа / сообщениям, обхода путей в архиве.

Не можем гарантировать защиту от: root / компрометированной ОС, кейлоггеров,
вредоносной клавиатуры, кражи пароля у владельца, атаки на незаблокированный телефон,
уязвимостей в Android/TDLib/криптобиблиотеках, слабого пароля или сохранения
расшифрованного архива в ненадёжное место после экспорта.

## Реализовано в исходном прототипе
- TDLib подключается к Telegram напрямую. **Никаких наших серверов**, ботов, прокси,
  аналитики, рекламы, телеметрии, crash-reporting SDK и трекинга нет.
- ЕДИНСТВЕННОЕ разрешение Android — INTERNET. Оно требуется, поскольку Telegram —
  сетевой сервис. Запретить IP других серверов только manifest нельзя: TDLib управляет
  сетевыми соединениями. Фактическое поведение проверяется сетевым аудитом.
- `allowBackup=false`, `usesCleartextTraffic=false`, `FLAG_SECURE` против скриншотов.
- Сессионный ключ TDLib завёрнут неэкспортируемым ключом Android Keystore.
- TDLib кэш в private directory приложения; копии файлов не пишутся в общую память.
- Архив сразу создаётся зашифрованным на URI через Storage Access Framework.
- Облачные Document Providers не допускаются по allowlist.
- Шифрование AES-256-GCM по блокам с authenticated final marker; PBKDF2-SHA256 400k.
- Проверяется весь архив после сохранения; код для проверки на Java/JVM протестирован.
- Logout только для сеанса TDLib текущего приложения, только после подтверждения.
- Архив не исполняется внутри приложения; не запускаем HTML/JS из переписки.
- Чаты `has_protected_content` и секретные чаты намеренно не экспортируются.

## Известные ограничения / для следующей версии обязательно
1. **Нет независимого аудита безопасности и пентеста.** Это НЕ продукт с доказанным нулевым риском.
2. **Нет Android SDK/официальной compiled libtdjson.so в пакете.** APK пока не собран/не запущен.
3. Нет фонового foreground-service: во время загрузки приложение лучше держать открытым.
   После прерывания сохранённые и зашифрованные страницы и медиа используются повторно;
   финальный .tva создаётся заново из checkpoint. Возобновление написано и проверено на JVM,
   но не протестировано на реальном Android/TDLib.
4. PBKDF2 — компромисс для стандартной Android JCA, план перехода на Argon2id
   или memory-hard KDF перед публичной версией.
5. Внутренний кэш TDLib может временно содержать незашифрованные медиафайлы;
   `logOut` очищает данные TDLib, удаление файлов на flash не равнозначно их
   гарантированному физическому уничтожению. Аппаратное шифрование телефона важно.
6. Требуется проверить корректность медиа-маппинга и историю реальных чатов,
   включая форумы, правки, альбомы, пересланные, редкие типы TDLib.
7. Пароль вводится через системную клавиатуру. Безопасность сторонней клавиатуры
   не контролируется нашим приложением. Не делиться паролем в одном канале с файлом.
8. Для выпуска нужна воспроизводимая подписанная сборка, проверка provenance
   official TDLib, аудит зависимостей и сетевого поведения.
9. Android SAF может оставить частичный зашифрованный файл после отмены/сбоя.
   UI пытается удалить его через ContentResolver; при отказе провайдера попросит удалить вручную.
   Это НЕ незашифрованный ZIP: он содержит лишь фрагмент шифротекста.
10. На отдельных устройствах нестандартный системный файловый провайдер
    локальной памяти может не пройти строгий allowlist: это безопасный отказ.
11. UI не покрывает все возможные новые способы авторизации TDLib (passkeys,
    QR, регистрацию и др.); приложение покажет неподдерживаемый этап.

## Изменения v0.6: безопасное возобновление

- В app-private `export-progress` находится только AES-GCM шифротекст сообщений, медиа и checkpoint.
- Сохранение файла и страницы завершается до обновления checkpoint; нечистый перезапуск
  не продвигает указатель истории вперёд и не помечает данные полностью скачанными.
- Доступные файлы с пустым кэшем скачиваются запросом `downloadFile` с `synchronous=true`,
  `offset=0`, `limit=0`; три попытки при временном сбое; после исчерпания — ошибка и возможность продолжить.
- Проверка итогового `.tva` обязательна перед удалением staging; при выходе staging очищается.
- Защита не гарантирует отсутствие утечек на взломанном телефоне.
- **Никакого независимого аудита, проверенной Android-сборки и теста реального входа пока нет.**
